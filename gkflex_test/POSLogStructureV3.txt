3 Summary
This document describes the XML structure of export POSLog v3.
There is a versioning of POSLog export because in future different versions of export should be supported.
Specification based on namespace:
"http://www.gk-software.com/storeweaver/sdc/pos_upload/pos_upload/2.5"
4 Structure
Under root element POSLog there is a element Transaction for each transaction.
Data types are according to the XML schema (XSD).
4.1 XSD
POSLog 2.5 XSDs - v.5.14.zip
4.2 Extensibility
4.2.1 Custom elements and attributes (customExtension)
For many elements and attributes the XSD contains a customExtension option, which is represented by an
"any" element or attribute in the XSD (with the "customExtension" namespace).
The use cases for these customExtensions are:
• In the GK Product POSLog the XXCustom fields from the Transaction DO are exported without
having defined them as elements or attributes in the XSD. The namespace prefix for exporting the
XXCustom fields is "CST", e.g. "CST:XXCustom01". If necessary, within the project it is possible to
deactivate exporting all XXCustom fields:
o This deactivation is not possible for single/specific XXCustom fields, only for all of them
together.
o This deactivation cannot be done via configuration, but requires a small implementation in
the project.
• In the projects, any required field can be added to the POSLog. The recommended namespace prefix
to be used for the project specific elements and attributes is also "CST". (Note: Such additional fields
can be used in case the export of the XXCustom fields is generally deactivated, but some content of
the XXCustom fields still needs to be exported.)
4.2.2 Additional Enumeration values
All enumeration data types have the TypeCodeExtension, which means there can be implemented additional
values for the corresponding elements and attributes without extending the XSD. This TypeCodeExtension
uses the following regular expression, which is the standard POSLog enumeration extension pattern:
